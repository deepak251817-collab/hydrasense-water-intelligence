# HydraSense ML Data Preparation & Isolation Forest Anomaly Detection (Phase 5A & 5B)

This directory contains the Machine Learning data preparation pipeline and Isolation Forest anomaly detection model for the **HydraSense Water Intelligence** platform.

## Overview & Scientific Disclaimer

> [!IMPORTANT]
> **Simulator Telemetry vs. Ground Truth**:
> 1. Telemetry generated by the sensor simulator is intended for system architecture development, pipeline verification, and stress testing.
> 2. Simulator scenario names are **NOT** treated as scientifically valid water-quality ground truth labels.
> 3. Real-world machine learning evaluation will integrate validated external public/research datasets placed in `ml/data/external/`.
> 4. **Unsupervised Anomaly Scoring**: Isolation Forest identifies observations that are unusual relative to the training telemetry. An anomalous reading indicates an unusual sensor or water-quality condition and does **NOT** by itself confirm chemical contamination.

## Feature Parameters

The ML pipeline strictly processes the four core water quality parameters and mandatory metadata:

- **Parameters**: `ph`, `turbidity`, `tds`, `temperature`
- **Metadata**: `station_code`, `device_id`, `timestamp`

---

## Data Cleaning & Range Validation Rules

### INVALID vs. UNUSUAL Data Policy

- **INVALID Data** (Removed during cleaning):
  - Values exceeding physical hardware or chemical limits:
    - **pH**: Outside `[0.0, 14.0]`
    - **Turbidity**: `< 0.0`
    - **TDS**: `< 0.0`
    - **Temperature**: Outside `[-10.0°C, 60.0°C]`
  - Non-numeric / missing mandatory metadata fields.

- **UNUSUAL Data** (Preserved during cleaning):
  - Statistical outliers that remain physically plausible (e.g. sudden drop of pH to 4.5, or spike of turbidity to 85 NTU) are **KEPT** in `clean_sensor_readings.csv`.
  - These unusual events represent real environmental spikes required by anomaly detection algorithms.

## Phase 5B — Isolation Forest Anomaly Detection

### 1. Mechanism & Motivation
Isolation Forest isolates anomalies by randomly selecting a feature and splitting values. Because anomalous observations are unusual and numerically distinct, they require fewer partitioning splits to isolate, resulting in shorter tree path lengths.

### 2. Training Strategy & Leakage Protection
- **Training Data**: Trained strictly on `ml/data/processed/train.csv` (70% earliest chronological observations).
- **No Lookahead**: Validation (`validation.csv`) and Test (`test.csv`) splits are **never** used during model fitting.
- **Reproducibility**: Default `random_state=42` ensures identical forest partitioning across runs.

### 3. Model Output & Schema (`anomaly_results.csv`)
Outputs are written to `ml/data/processed/anomaly_results.csv` with schema:
- **Metadata**: `station_code`, `device_id`, `timestamp`
- **Telemetry**: `ph`, `turbidity`, `tds`, `temperature`
- **Model Outputs**:
  - `anomaly_score`: Raw Isolation Forest decision function score (where lower/negative values indicate a higher degree of unusualness).
  - `anomaly_label`: Binary classification mapping:
    - `0` = **Normal** (`inlier`)
    - `1` = **Anomaly** (`outlier`)

### 4. Technical Interpretation & Limitations
- **No Ground-Truth Claims**: Because ground-truth contamination labels are not available, precision/recall/ROC-AUC metrics are not reported. Evaluation remains strictly unsupervised and qualitative.
- **Wording Policy**: Outputs explicitly use "normal" vs "anomaly". Misleading terms ("contaminated", "polluted") are prohibited.

## Running the Pipeline & Scripts

### 1. Export Raw Sensor Data
```bash
python ml/scripts/export_sensor_data.py
```

### 2. Data Quality Report
```bash
python ml/scripts/data_quality_report.py
```

### 3. Clean Sensor Data
```bash
python ml/preprocessing/clean_data.py
```

### 4. Create Chronological Splits
```bash
python ml/scripts/create_splits.py
```

### 5. Train Isolation Forest Model
```bash
python ml/scripts/train_isolation_forest.py --contamination 0.05
```

### 6. Detect & Score Anomalies
```bash
python ml/scripts/detect_anomalies.py
```

### 7. Evaluate Model (Unsupervised Summary)
```bash
python ml/scripts/evaluate_isolation_forest.py
```
